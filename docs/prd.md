# BaaS 跨链平台 PRD（v1.0）

## 1. 文档信息
- 项目名称：金赋水 BaaS 跨链平台
- 版本：v1.0
- 阶段：需求确认版（可进入技术设计）
- 目标读者：产品、架构、后端、前端、测试、安全、运维团队

## 2. 项目背景与目标
### 2.1 背景
内部团队需要统一的区块链基础服务平台，解决多产业业务“快速上链、合约统一部署、链与节点治理”的问题，并为未来“金赋水链接入 + 跨链生态扩展”建立标准化底座。

### 2.2 目标
1. 提供产业数据上链 API/SDK，实现一站式上链接入。
2. 提供跨链智能合约管理与部署能力，提升上线效率。
3. 建设链/节点/用户/身份综合管理体系。
4. 集成多链区块链浏览器，实现跨链数据可观测。
5. 支持未来接入自研金赋水链，逐步走向跨链生态。

### 2.3 非目标
- 完整跨链资产桥闭环（锁铸/销毁释放）
- 对外商业化计费结算系统
- 公有云市场化多租户运营后台

## 3. 目标用户与角色
### 3.1 目标用户
- 内部开发团队（核心）
- 内部运维与安全团队
- 产业应用接入方（后续）

### 3.2 角色
- 平台超级管理员
- 租户管理员
- 开发者
- 审计员
- 只读访客

## 4. 功能范围总览
平台包含 6 大模块：
1) 数据上链模块
2) 集成化区块链浏览器
3) 合约上链模块（跨链部署）
4) 链与节点管理模块
5) 链上数字身份登记认证模块（DID + CA + 国密）
6) BaaS 用户管理体系（RBAC + 自助门户 + UBA）

## 5. 详细功能需求
### 5.1 数据上链模块
#### 5.1.1 产业数据上链 API
- 支持 JSON 与文件哈希上链
- 同步提交 + 异步回执查询
- 幂等请求、防重复上链
- 批量上链任务
- 返回 requestId / txHash / chainId / blockHeight / status / errorCode

#### 5.1.2 SDK 套件
- 首期 SDK：Java / Node.js（可扩展 Go）
- 封装签名、重试、超时、回调
- 提供示例工程与接入文档

#### 5.1.3 上链任务管理
- 状态：待提交/已提交/确认中/成功/失败
- 失败分类：链上拒绝、Gas不足、节点异常、签名异常
- 支持手动/自动重试

### 5.2 集成化区块链浏览器
#### 5.2.1 多链概览
- 链高度、TPS、24h交易量、活跃地址数
- 节点健康状态概览

#### 5.2.2 核心查询
- 区块查询
- 交易查询
- 地址查询
- 合约查询

#### 5.2.3 全局搜索
- 支持区块号 / TxHash / 地址 / 合约地址

### 5.3 合约上链模块（跨链智能合约部署）
#### 5.3.1 合约模板管理
- 模板上传、版本管理、标签分类
- 环境参数配置（测试/预发/生产）

#### 5.3.2 在线编辑与构建
- 编辑、语法校验、依赖与版本校验
- 部署前参数预览与确认

#### 5.3.3 一键跨链部署
- 选择目标链批量部署
- 输出逐链部署结果
- 失败链支持重试/回滚

### 5.4 链与节点管理模块
#### 5.4.1 链管理
- 链注册（chainId、RPC、浏览器地址、网络标识）
- 配置版本化与变更追溯

#### 5.4.2 节点管理
- 节点池（主备、权重、故障切换）
- 在线/离线/同步进度/延迟实时监测
- 告警（离线、同步停滞、超时）

#### 5.4.3 链事务清单
- 按链查看事务队列与执行状态
- 支持按时间/状态/业务筛选

### 5.5 链上数字身份登记认证模块
#### 5.5.1 DID 体系
- DID 创建、绑定、吊销
- 主体支持：个人/企业/设备（可配置）

#### 5.5.2 CA 对接与国密
- 对接数字 CA
- 支持 SM2/SM3/SM4

#### 5.5.3 认证与存证
- 身份凭证摘要上链
- 验签与有效性查询
- 撤销状态校验

### 5.6 BaaS 用户管理体系
#### 5.6.1 RBAC
- 角色与权限点可配置
- 资源级权限控制

#### 5.6.2 自助门户
- 注册、资料修改、密码找回
- 多因素认证预留

#### 5.6.3 API Key/Token
- 创建、轮换、吊销
- 配额与白名单（可选）

#### 5.6.4 UBA
- 用户行为分析
- 异常行为识别与风险预警

## 6. 用户故事（节选）
1. 开发者通过统一 API 将业务数据上链并追踪状态。
2. 管理员在控制台统一管理多链与节点健康。
3. 合约开发者一次操作将合约部署到多链并获取逐链结果。
4. 审计员查看关键操作日志并追溯责任人。
5. 产业用户完成 DID 登记并可被链上验证。

## 7. MoSCoW 优先级
### Must
- 数据上链 API + SDK
- 浏览器核心查询
- 跨链合约部署基础版
- 链/节点管理与告警
- DID 登记认证基础版
- RBAC + 自助门户 + 审计日志

### Should
- 批量任务编排增强
- 多链高级检索与聚合统计
- UBA 风险策略可视化

### Could
- 自动链路由优化
- 合约灰度发布策略
- 智能告警编排

### Won’t
- 完整跨链资产桥
- 商业化计费结算
- 对外 SaaS 商城化能力

## 8. 非功能需求
### 性能
- 上链接口 P95 ≤ 800ms（不含链上确认）
- 查询接口 P95 ≤ 500ms

### 可用性
- 核心 API 可用性 ≥ 99.9%
- 节点故障自动切换

### 安全
- 全链路 TLS
- 请求签名 + 防重放
- 审计日志不可篡改
- 最小权限原则

### 合规
- 国密支持
- CA 流程合规
- 日志留存可配置

## 9. 数据与接口概要
### 核心实体
Tenant, User, Role/Permission, Chain/Node, OnchainTask, ContractTemplate/Instance, DIDProfile/Credential, AuditLog

### 关键 API 示例
- POST /api/v1/onchain/data
- GET /api/v1/onchain/tasks/{id}
- POST /api/v1/contracts/deploy
- GET /api/v1/explorer/search?q=
- POST /api/v1/did/register
- POST /api/v1/auth/verify-signature

## 10. 验收标准
1. 至少 2 条链接入成功并可稳定调用上链接口。
2. 上链任务可全流程追踪。
3. 合约可在多链部署并返回结果。
4. 浏览器支持区块/交易/地址/合约查询。
5. 节点看板支持在线/离线/告警/同步状态。
6. DID 实现登记-认证-撤销闭环。
7. RBAC 阻断越权，审计日志可追溯。

## 11. 里程碑建议（8周）
- 第1-2周：链适配、上链接口、SDK
- 第3-4周：浏览器基础、链/节点管理
- 第5-6周：合约部署、RBAC 与门户
- 第7周：DID + CA + 国密联调
- 第8周：测试、压测、安全验证、UAT

## 12. 风险与应对
1. 多链差异大 → 适配层插件化
2. 节点稳定性风险 → 多节点池 + 自动切换
3. 国密/CA 对接复杂 → 提前 PoC 并行联调
4. 权限复杂 → 核心角色先落地再细化
